Enterprise Admin Guide

GitHub Copilot Cost Centers & AI Credit Pools

How to fence a team's AI-credit spend, protect the shared enterprise pool, and give a group its own budget — via the UI and the REST API. For GitHub Enterprise Cloud admins on usage-based billing.

How the pool works

Under usage-based billing, Copilot usage is metered in AI credits (1 credit = $0.01 USD). Each Copilot Business/Enterprise license brings a fixed monthly amount of included credits, and by default all included credits are pooled at the enterprise level — every user draws from one shared pool. When that pool is exhausted, additional usage is metered (and billed, or blocked, depending on your budgets).

A cost center lets you carve a group out of that shared model: its own fenced pool, its own budget, and optionally its own Azure billing.

The four control levels

ControlWhat it capsHard stop?
User-level budget (universal / cost-center / individual)One user's total credit use — pool and meteredAlways
Included-usage cap (AI credit pool on a cost center)How much of the shared pool a cost center can drawBlock or allow overage
Cost-center budgetA cost center's metered spend after its poolOnly if "Stop usage" enabled
Enterprise / org budgetMetered spend at that scopeOnly if "Stop usage" enabled
Precedence: individual ULB > cost-center ULB > universal ULB. And across scopes, the most restrictive budget wins — a low enterprise budget can block a cost center before its own limit is hit.

What the cost-center pool does (and doesn't)

  • Does: fences a group to its own licenses' worth of the shared pool, so it can't drain credits other teams paid for. GitHub computes the cap automatically from the licenses assigned to the cost center and adjusts it as licenses change.
  • Doesn't: mint extra included credits. The cap is a fence, not a top-up. To give a group more capacity: (a) assign more/higher-tier licenses to the cost center, or (b) attach the group's own Azure subscription and let it run metered overage under a cost-center budget.

Best practice: enable it near the start of a billing month — changes apply going forward only — and put every licensed user in a cost center (an enterprise-level budget makes a good catch-all for anyone not yet assigned).

Availability: included-usage caps for cost centers are currently REST API-first; management in the cost-center settings UI is rolling out. Everything below works via the API today.

Setup — UI

1
Enterprise → Billing and licensing → Cost centers → New cost center. Give it a name.
2
Optional: add the group's Azure subscription to bill its usage directly (credentials are verified against Azure).
3
Under Resources, add an enterprise team (membership auto-syncs via IdP/SCIM) or individual users.
4
Billing and licensing → Budgets and alerts → New budget → SKU-level budget → product Copilot, SKU Copilot AI credits → scope to the cost center → set amount → optionally Stop usage when budget limit is reached → enable 75/90/100% alerts.

Setup — REST API

Uses GitHub CLI (gh); adapt to curl as needed. Requires an enterprise owner / billing manager token with manage_billing:enterprise (and read:org for team sync). Replace ENTERPRISE with your enterprise slug.

1 · List existing cost centers (auth check)

gh api \
  -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  /enterprises/ENTERPRISE/settings/billing/cost-centers

2 · Create a cost center

gh api --method POST \
  -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  /enterprises/ENTERPRISE/settings/billing/cost-centers \
  -f 'name=Team-Name'
# → returns { "id": "<COST_CENTER_ID>", ... } — keep the id

3 · Add resources (team or users)

gh api --method POST \
  -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  /enterprises/ENTERPRISE/settings/billing/cost-centers/COST_CENTER_ID/resource \
  --input - <<< '{ "users": ["user-1","user-2"], "enterprise_teams": ["team-slug"] }'
# reassigned_resources[] in the response lists anything moved from another cost center

4 · Set an AI-credits budget on the cost center

gh api --method POST \
  -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  /enterprises/ENTERPRISE/settings/billing/budgets \
  -f budget_type='SkuPricing' \
  -f budget_product_sku='copilot_ai_credits' \
  -f budget_scope='cost_center' \
  -f budget_entity_name='COST_CENTER_ID' \
  -F budget_amount=1000.0 \
  -F prevent_further_usage=true \
  -f budget_alerting='{"will_alert":true,"alert_recipients":["admin-username"]}'

5 · Set an individual / cost-center user-level budget

# scope=user for an individual; budget_amount is USD (credits ÷ 100)
gh api --method POST \
  -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  /enterprises/ENTERPRISE/settings/billing/budgets \
  -f budget_type='SkuPricing' \
  -f budget_product_sku='copilot_ai_credits' \
  -f budget_scope='user' \
  -f budget_entity_name='login' \
  -F budget_amount=28.0 \
  -F prevent_further_usage=true
Watch-outs.
  • "Stop usage" is OFF by default on cost-center/org/enterprise budgets — pass prevent_further_usage=true for a hard stop. ULBs always hard-stop.
  • Budgets don't sum across levels — an enterprise budget isn't the total of your cost-center budgets; reconcile totals yourself.
  • One budget per cost center for a given SKU — you can't set different budgets for teams inside the same cost center. Need separate limits? Separate cost centers (they can share one Azure billing identity).
  • When AI credit pool is enabled, only users and enterprise_teams are valid resources (orgs/repos carry no per-license entitlement to size a cap from).

Automating it

The REST calls above are the building blocks — wrap steps 2–4 in a script keyed off your team roster and run it on a schedule (cron, a CI job, or a scheduled GitHub Actions workflow) to keep cost centers and budgets in sync as membership changes.

For usage reporting, see the billing REST endpoints and the automate usage reporting tutorial.

On the community sample: there is a GitHub-published cost-center-automation repo (MIT). Its team/repo → cost-center sync logic is reusable, but note its budget layer still targets the retired copilot_premium_request (PRU) SKU and it predates the AI-credit pool / included-usage-cap and cost-center user-level-budget features. It also hasn't seen active maintenance since late 2025. Treat it as a scaffold to adapt, not a current, drop-in tool — the authoritative source is the REST API and docs referenced below.
